# 빌드 정리 정책

## 대상과 실행

브라우저용 React/Vinext/Vite + Rust/Bevy ECS/WASM 게임이다. Cloudflare Worker와
Sites 배포 메타데이터를 사용한다. PC 네이티브·모바일 앱·콘솔 빌드 정의는 없다.
Node 22.13+, Python 3.9+가 필요하며 정리 도구의 지원 호스트는 macOS/Linux이다.
Windows에서는 WSL/Linux CI를 사용한다. Rust 재컴파일에는 기존 README의 도구가 필요하다.

| 명령 | 동작 |
| --- | --- |
| `npm run build` / `npm test` | 격리 웹 빌드 → 기존 HTML/WASM 테스트 → 검증된 결과 게시 → 정리 |
| `npm run engine:build` | 격리 Cargo/wasm-bindgen → WASM 동작 테스트 → `public/wasm` 교체 → 정리 |
| `npm run build:release` | 웹 빌드·검증 후 개수 제한 없는 출시 보관 패키지 생성 |
| `npm start` | 특정 성공 패키지를 읽기 잠금으로 고정하고 실행; 종료 후 정리 |
| `npm run build:clean` | 소유권과 잠금을 확인해 죽은 작업 회수 및 보관 정책 실행 |
| `npm run test:cleanup` | 작은 가상 산출물로 실패·중단·복구·동시 실행·보관 제한 테스트 |

실제 배포는 기존 Sites 배포 절차를 사용한다. `build:release` 자체는 원격 배포를
하지 않는다. GitHub Actions는 같은 빌드 경로 및 `always()` 정리를 실행한다.
CI 개발 패키지·원문 로그의 원격 아카이브 업로드를 추가하지 않아 실행마다 복제되지
않는다. GitHub 자체 콘솔 로그의 서비스 보관 설정은 이 로컬 파일 정책과 별개다.

## 소유권, 장애 복구, 게시

- `.build/owner.json`이 프로젝트의 절대 경로와 소유 도구를 기록한다. 작업 폴더는
  `.build/jobs/<UUID>`이며 상위 폴더는 권한 0700으로 만든다. 임의 경로 인자는 받지 않는다.
- 프로젝트 메타데이터 잠금과 작업별 `flock`을 쓴다. 자식에게 잠금 FD를 상속하고
  프로세스 그룹도 확인하므로 부모 강제 종료만으로 작업 폴더를 지우지 않는다.
  PID 재사용/권한 문제로 생존 여부가 불명확하면 보존하고 경고한다.
- SIGINT/SIGTERM/SIGHUP은 자식 그룹에 종료를 전달하고 5초 후 강제 종료한다.
  정상·오류·중단은 `finally`로 정리한다. SIGKILL/전원 차단 잔여물은 다음 명령에서
  소유 표식과 잠금/프로세스 상태를 확인한 후 회수한다. 표식이 없거나 깨진 폴더는
  자동 삭제하지 않는다. 경고에 남은 경로가 표시되며 `build:clean`은 경고 시 실패한다.
- 입력은 Git 추적 파일과 무시되지 않은 작업 파일, 로컬 `.env*`를 사본으로 만들며
  외부 소스 심볼릭 링크는 명시적 정책 없이 복사하지 않는다. 의존성은 패키지별 링크로
  재사용하고 Vite config 임시 파일·optimizer cache·Wrangler/Miniflare registry·
  TMPDIR·Cargo target은 작업 폴더 안에 둔다. 작업 사본에만 폰트 캐시의 절대 경로를
  보정한다. 원본 폰트와 사용자 상태는 바꾸지 않는다.
- 완성한 패키지는 검증 후 `.build/packages/<UUID>/output`으로 옮긴다. `dist`는
  이를 가리키는 심볼릭 링크로 원자 교체한다. 최초 기존 디렉토리는 `preserved`에
  옮겨 보존한다. 최초 전환/엔진 디렉토리 교체 사이에 중단되면 게시 저널로 이전
  결과를 복원한다. 엔진의 최초 원본은 보존하고 이후 도구가 만든 동일 설치본은
  해시로 확인해 중복 백업을 정리한다. 원본 변경이 감지되면 별도 보존한다.
- `npm start`의 읽기 잠금은 사용 중인 이전 패키지 삭제를 막는다. 외부 서비스나
  수동 도구가 패키지를 장기간 참조하려면 출시 보관본을 사용하거나 동일한 읽기
  잠금을 획득해야 한다. 새 소비자/패키징 도구도 이 규칙에 통합한다.
- 파일시스템 장애 중 저널/소유 표식이 손상되면 경고 후 수동 복구가 필요하다.
  전원 차단을 실제로 발생시키는 검증은 수행하지 않는다.

## 보관 범위

| 종류 | 정책 |
| --- | --- |
| 개발 성공 패키지 | 웹/엔진 각각 최근 2개. 서로 다른 산출물이므로 도구별 계산. 현재 `dist`와 사용 중 패키지는 보호 |
| 원문 로그 | `.build/logs/<UUID>/output.log`, 성공·실패·중단 포함 전체 최근 10회, 각 앞부분 최대 1MiB. 한도 초과 경고, 상태는 `result.json` |
| 출시·업데이트·롤백 | `.build/releases` 및 `.build/preserved`: 자동 만료 없음. 배포 담당자가 용도를 확인한 뒤 별도 승인된 정리 |
| 심볼/매핑 | `.build/symbols/<package UUID>`에 보존; `.map/.pdb/.debug/.sym/.dSYM`을 개발 패키지 제한과 분리. 새 형식은 도구 도입 시 등록 |
| Rust 브라우저 설치본 | Git 추적 `public/wasm` 유지. 엔진 성공 패키지와 별도로 앱의 입력 역할을 함 |
| 의존성/다운로드 | `node_modules`, npm/Cargo 공용 캐시, `.vinext/fonts`는 빌드마다 삭제하지 않음. 현재 폰트 캐시는 약 172KiB라 별도 만료 불필요 |
| 사용자/로컬 상태 | `.wrangler/state`, DB 마이그레이션, 저장 데이터, 환경·인증·서명 정보는 정리 대상 아님 |
| 감사 기록 | `docs/disk-cleanup/` 측정·삭제 목록·보존 해시·검증 요약은 빌드 로그 순환 대상 아님 |

개발용 `npm run dev`는 실시간 소스를 사용하며 Vite의 기존 optimizer 캐시와 폰트
캐시를 다시 만들 수 있다. 이는 고정 경로 캐시이고 번호별 빌드 사본은 아니다.
공용 의존성 캐시 용량 조정은 실제 증가를 측정한 별도 작업으로 수행한다.
